# Salla Review — CI & Git Hooks

This folder was generated by the **Salla Theme Reviewer** VS Code extension
("Salla Review: Setup Git & CI Checks"). It contains a self-contained copy of the
review engine (plain Node.js, zero dependencies) so that git hooks and GitHub
Actions can run the exact same checks as the editor — for every teammate and on CI,
with nothing to install.

## What was set up

| File | Purpose |
|---|---|
| `.salla-review/` | The vendored engine + `cli.js` (this folder) |
| `.githooks/pre-commit` | Fast local gate — errors block the commit |
| `.githooks/pre-push` | Full gate incl. the npm version check — errors block the push |
| `.github/workflows/salla-review.yml` | CI gate on every push and pull request |

The hooks are activated via `git config core.hooksPath .githooks` (local to this
clone). **Teammates must run that command once after cloning**, or re-run the
extension's setup command.

To gate merges, enable branch protection on GitHub and require the
**Salla Theme Review** check.

## Configuration

All three surfaces (editor, hooks, CI) read `sallaReview.*` keys from
`.vscode/settings.json` in this project — check toggles, `include`/`exclude`
patterns, and `ignoredTexts` apply identically everywhere. Commit that file to
share the configuration with the team.

## Bypassing

- One commit/push: `git commit --no-verify` / `git push --no-verify`
- Via environment: `SALLA_REVIEW_SKIP=1 git commit ...`

## Updating

Re-run **"Salla Review: Setup Git & CI Checks"** from VS Code after updating the
extension — it refreshes the engine copy (including the Raed reference fingerprint)
and rewrites the hooks and workflow. Commit the changes.
